# claude-workflow

## Code conventions

- The run log only grows: no record is dropped or rewritten when its format changes, and every reader handles every past `schema` version, treating a missing field as absent.
- A new run-record field raises `schema`, and its `SCHEMA` text names the schema that added it, so a reader can tell a record that should carry the field from one that predates it.
- `workflow-report.py --json` carries a `version`: adding keys keeps it; renaming or removing a key bumps it.
- In `--json`, a fact the report could not read (a run with no window, a dispatch with no subagent transcript) is `null`, never `0` or empty.
- A `--json` unit's `key` is the dashboard's recipe and never changes while `version` is 1: the first 16 hex characters of the SHA-256 of `date|project|branch` for a run (a missing or non-string field as the empty string) and of its `file` for a session.
- Output that holds personal data (the report's JSON and page, the ledger archive) is written outside every repo and is never exported.
- The `--html` page is built only from `report_data`'s dict, with no script and nothing loaded from outside; every value goes through `cell`, which escapes it and shows null as `–`.
- An agent whose report is checked ends it with one fixed `Name: key=N key=N` count line, which `--health` reads.
- `read_runs` cleans each run record once, keeping the parsed record as `_raw`: a malformed value reads as absent (None, 0 or `[]`), a step that is not a dict of a known kind is dropped, and a bool never counts as a number.
- Transcript usage counts once per `message.id`, from the row with the most output tokens.
- A call's context is the input, cache-read and cache-write tokens of its message's largest own iteration, counted once per `message.id` like its spend.
- A tool call's class comes from `tool_class` alone, and a Bash call is classed by its first command after any leading prefix `BASH_PREFIX` strips, `cd <dir> &&` or `cd <dir>;` included; a tool result counts under its call's class, matched by id within the unit's main transcripts, else under `other`.
- `PRICES` holds one price per model ID with its date suffix stripped; a model it lacks shows tokens only, with cost `null`.
- A run that spans a weekly usage reset (its `started` and `date` in different weeks, or, lacking either, points that went down) has `null` points in `run_entry`, and every points sum adds only the known ones.
- A run window is `(start, end]` compared as transcript timestamp strings: a time from anywhere else goes through `stamp` first.
- A definition a script can't import, from a hook or a test, is copied under a `keep them the same` comment naming its source.
- The dashboard page is published only by `/workflow-dashboard`, as a private artifact whose link is kept in `~/.claude/workflow-dashboard-artifact.txt`, so each run updates the same artifact.
- Tests point every `~/.claude` path option of the report (`--projects`, `--log`, `--agents`, `--export-stamp`, `--cache`) into their temp folder, so none reads the real home.
- The parse cache never changes the report's output: every mode prints the same with `--no-cache`, which a test compares, and a change to what a cached part holds bumps `CACHE_VERSION`. The reporter writes only under its `--cache` folder, each file through `write_atomic`.
- A script that acts on a checkout (`failing-test-check.py`, `wave.py`) prints one JSON object on stdout and exits 0 when done, 1 when the state isn't what it expects and 2 on a usage error (on stderr, nothing on stdout), with 3 for `failing-test-check.py`'s `couldnt_run`; a refusal changes nothing.
- `wave.py` finds a task's worktree by its branch in `git worktree list`, never from a path rule, so it works from any worktree of the repo; `start` places them under its own checkout's `.worktrees/`, keeping concurrent runs in different worktrees apart.
- A new skill or command gets a row in the README's `### Offered skills and commands` table, with its moment or "never offered" and why, and an offered one gets its moment in the **Offers** bullet of `claude-md/agentic-workflow.md`.
- Every WARN is built as `problem(kind, text, step, skill, agent)` and turned into a `warning` dict with its full line and its run or session. `--json` gives each list as `warns` (its texts) and `warnings` (the dicts), and sites that report the same fact share its kind. A kind, once published, is never renamed or removed while `version` stays 1; a new check adds one.
- A session's or run's title is the last `custom-title` row of its main transcript, read over the whole file and not the run's window, and never from the `custom-title.json` beside it.
- A record's step is tied to a dispatch only when certain, through `tie_steps`: by its `agent_id` when no other step carries it and exactly one dispatch of its kind has that id, else when it has no `agent_id` and its kind has exactly one step and one dispatch; never by order, and an untied step's tied facts are `null`; a `simplify` step takes the window's only simplify call's time when it is the record's only simplify step.
- `--health` compares a schema 4 record's step only with the dispatch `ties_by_id` gives it and warns on each other step but simplify with why it is untied (a missing, unknown or mismatched agent id, or once per shared id); older schemas compare the n-th step of a kind with the n-th launched dispatch of that kind.
- Finding categories, their tie-break rule and the validity definitions live in `CATEGORIES` in `workflow-report.py`, with a version: an id is permanent (a new version adds ids, retires one, kept and marked, or rewords text, and never reuses, renames or removes one), any change bumps the version, and each reviewer agent carries its area's current list under `keep them the same`.
- Every transcript row belongs to one unit: the exported run whose window, among those holding it, ends first, else its transcript's session, with one message-id and one tool-id dedup across units; every `--json` total is computed from the units' exported facts.
- An event two main transcripts hold, as a forked session's copied rows do, counts once, by `event_key` (its time, kind and value), in the first unit read that holds it: the runs oldest first, then the sessions by path; a session's commands and typed triggers are those its transcript owns, and a typed trigger is met when any transcript holding its row loads the skill later, and warns once, on the first transcript by path.
- `--health` and `--brief` default `--since` to `HEALTH_DAYS` (7) days before `--now`, set in `main`; `--json` and `--html` read everything, and the trial counts every record.
- Only `--changed-since` reads or writes the export state and prunes the cache, under `state.lock`; every other mode leaves both untouched, and the cursor names the state's id so a rebuilt state never passes for the old one.
- A unit's `phases` are counted in the pass that counts its `models` and `advisor`, so they add up to them; a message's phase comes from its transcript and its row's time.
- In `--json`, a collection whose entries can drop out between exports is a list, since the dashboard merges objects key by key and replaces lists whole.
- A session's start, end, project and slash commands are its main transcript's, never split by run windows; start, end and project are read over the whole file, like its title, and a command is kept by name and time only, its arguments never read; a command, like a typed trigger, counts by its own row's `origin` (kind `human`, or none outside a compaction summary), never by the transcript-level `has_origin` rule, since built-in commands such as `/model` carry no origin.
- A run record is tied to its session only by its `started` or `head` value appearing, in JSON, Python or shell-escaped quotes, in the main-transcript Bash command that wrote it, never by time or order; a record built from shell variables stays untied.
- When a transcript ran is decided by its rows' timestamps; the file's modification time only screens out files older than the window, since the app rewrites old transcripts' metadata rows.
- A run's window is the chain of transcripts read backward from the one that wrote its record, through each `start_session` call whose brief starts with `Handoff <n>:`, started a session and opens the successor's first user row; every fact of the window reads the whole chain, and a `start_session` without the marker starts a new unit.
- A session unit reads only its own transcript, and a run reads each transcript of its chain with that transcript's own windows, so a predecessor's rows after its handoff call stay its session's.
- `agent_off_pin` reads the pins from today's agent files for every run in the log, so when a seat moves its old pin keeps passing through a `PAST_PINS` row beside `TRIAL_RUNS` (agent: the last UTC day of the old pin, its model, its effort), for dispatches on or before the day the new seat was installed, whatever the run's finish date; the row's day is set to the install day in the change that merges with it, and a row is never removed.
- A skill counts as loaded by a `Base directory for this skill:` row or by the session-start hook's using-superpowers block, read from a SessionStart hook row only (so once per start, clear or compaction), and a tag quoted in a prompt, a queued prompt, a tool result or another hook's output never counts.
- A pair's second half is a `final-reviewer` dispatch passing Fable that launched when exactly one final review had launched since the last `simplify` and that one did not pass Fable, judged from dispatch inputs by `pair_halves` in the reporter and by the same rule in the dispatch hook, except that the reporter counts the start of its events as a `simplify` where the hook needs one; it is no record step and enters no fix round, and the hook's rule and the reporter's tolerance stay after the measure ends, since the transcripts that hold pairs stay in the log.
- `PAIRS` beside `TRIAL_RUNS` matches the ten pairs of the **Measure (pairs)** bullet, and `PAIRS_FROM` its copy in the tests, under `keep them the same`; `--brief` counts the pairs from `PAIRS_FROM` whatever `--since` says and prints no line at zero.
